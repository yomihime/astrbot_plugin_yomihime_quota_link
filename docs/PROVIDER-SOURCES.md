# 余额与额度查询：接口与来源

本轮以公开接口和固定版本的开源实现核对请求行为，再独立编写 Python 适配器。项目保留各来源原有许可证，未复制第三方实现代码。公开文档给出接口契约，固定源码补充字段含义和客户端实际行为。

原有预设包括 DeepSeek 账户余额（普通 Bearer）、阿里云百炼 BSS 资金与信用额度（RAM 签名）、Grsai 账户积分（请求令牌）、Meinianda 站内额度（API Key）及按账户配置的 OpenAI 兼容接口映射。

固定站点使用官方 HTTPS 地址及选定地区的接口。自建网关的地址仅接受 HTTPS 根地址。已有查询凭据时，需先清除凭据才能更改站点。所有适配器使用现有 HTTP 客户端，无跨站、自动探测或其他凭据回退，也不跟随重定向。

HTTP 401/403 分别归类为凭据拒绝和权限不足，429 进入上游共享限流，5xx、连接错误和超时使用现有暂不可用及退避逻辑。可解析的 `Retry-After` 保留到查询服务，网关按站点、区域接口按地区隔离限流和串行队列。业务响应必须符合该接口的成功契约，未知失败和格式异常不显示为零。响应文本、模型 Key 与管理密钥不进入错误文案。

账户余额预设使用可用余额作为预警候选，xAI 使用单独的已入账预付余额指标。预警沿用已有单位观察和确认流程。MiniMax、GLM、New API 与 Sub2API 保留手动查询能力，周期数值和 Key 限额不参与低余额预警。
